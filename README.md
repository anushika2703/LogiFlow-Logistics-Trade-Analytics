# LogiFlow — End-to-End Logistics & Trade Data Pipeline

A runnable portfolio project tailored to a **Custom & Trade / International Data Analyst** role. It demonstrates an end-to-end local data workflow: ingestion, data-quality checks, cleaning, transformation, SQL loading, KPI reporting, and an interactive Power BI-style dashboard.

> **Data honesty:** The starter dataset is synthetic and generated by this project. It is not Volvo Group data and the project is not affiliated with Volvo. Duty amounts are illustrative only and must not be used for real customs decisions.

## Features

- **Ingestion:** Reads `data/raw/shipments_raw.csv`; creates a synthetic dataset on first run.
- **Quality checks:** required fields, duplicate shipment IDs, positive declared values, missing-value handling.
- **Transformation:** delay days, on-time/delayed flags, estimated duty, and operational exception categories.
- **Storage:** loads cleaned records and quality audit into SQLite (`data/processed/logistics_analytics.db`).
- **Analytics:** shipment volume, on-time rate, delays, customs exceptions, estimated duties, route/mode performance.
- **Dashboard:** Streamlit + Plotly, with filters and downloadable exception worklist.
- **Outputs:** cleaned CSV, summary KPI CSV, exception worklist CSV.

## Quick start (Windows)

1. Extract the ZIP.
2. Install **Python 3.10 or newer** from https://www.python.org/downloads/ and enable “Add Python to PATH”.
3. Double-click `run.bat`.
4. The first run creates a virtual environment, installs dependencies, runs ETL, and launches the dashboard in your browser.

If Windows blocks the script, open PowerShell in the project folder and run:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python run_pipeline.py
streamlit run dashboard.py
```

## Run pipeline and dashboard separately

```bash
python run_pipeline.py
streamlit run dashboard.py
```

## Expected source CSV schema

If you provide your own CSV using the dashboard uploader or replace `data/raw/shipments_raw.csv`, include these columns:

| Column | Meaning |
|---|---|
| `shipment_id` | Unique shipment identifier |
| `shipment_date` | Shipment date |
| `origin_country`, `destination_country` | Route endpoints |
| `transport_mode` | Road, Air, Ocean, Rail, etc. |
| `product_category` | Goods/product group |
| `customs_status` | Cleared, Pending Review, Inspection, Documentation Hold, etc. |
| `declared_value_usd` | Declared value in USD |
| `weight_kg` | Shipment weight |
| `planned_transit_days`, `actual_transit_days` | Planned and actual transit duration |
| `documents_complete` | Boolean or true/false |
| `duty_rate` | Illustrative decimal rate (e.g. 0.05 = 5%) |
| `supplier_id` | Supplier identifier |

The pipeline expects the above fields. For the most reliable result, use ISO-like dates (`YYYY-MM-DD`), positive declared values, and numeric transit/weight fields. Missing weight and transit values are imputed; invalid/nonpositive declared values are removed; duplicate shipment IDs are deduplicated.
